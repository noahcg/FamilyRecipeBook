# Recipe unit presentation and imports

The account's metric switch is a viewer preference. Imported and manually entered recipes keep their parsed or entered ingredient quantities, units, and instruction text as the active source in the recipe tables. Imports also retain a structured `import_metadata.unit_source_v1` snapshot of parsed ingredients and instructions; edits do not rewrite that snapshot. File import metadata, source URLs, and uploaded original images retain their existing provenance behavior. The app does not persist rounded conversions as a second source.

Photo/OCR and pasted imports project recognized units into the current viewer's preference before populating the review form. File imports project their preview, then save the parsed source. The recipe detail, offline view, print view, and signed-in shared view project from the saved source for each viewer. Public anonymous shared views retain the source units as written. The app layout resolves the account preference on the server before rendering its form and recipe views.

When an editor opens a recipe, the form projects from the stored source. If a projected ingredient quantity and unit or instruction is unchanged on submit, the exact stored source field is saved again. An edited field becomes the new active source. This preserves precision through repeated saves and preference changes, while honoring edits. The form does not offer an **Original** toggle: imported source can be partially replaced by later edits, and older recipes do not all have a recoverable full import snapshot. The snapshot is provenance, not a value to restore over edits. The attached original image and import provenance remain available through their existing features where present.

Conversions are deliberately narrow. Supported simple weight and volume units, fractions, ranges, and explicit Fahrenheit/Celsius temperatures are projected. Counts, package descriptions, ambiguous or unrecognized units, ingredient notes, and unstructured measurement references in instruction prose are left as written. Cup and volume conversions stay volume; no universal ingredient density is assumed. Teaspoons use the product's 5 mL convention. Oven temperatures display to the nearest practical 5 °C or 25 °F. Conversion occurs on each viewer's private render path; it does not update collaborators' stored content or account settings.

The ingredient entry keypad follows the same account preference. Metric entry offers mL, L, g, kg, can, and each plus a decimal key; other units remain available through Manual entry. Imperial entry retains its prior shortcuts and fraction key. Switching units in the editor changes the active value only when the user edits the ingredient.
